## 초조한 전망대는

빠르게 흘러가는 뉴스를 일회성으로 소비하지 않고, 각자가 선택한 주제를 4개월 동안 지속적으로 **관찰하고, 기록하고, 해석하는** 읽기·쓰기·에이전트 실험 프로젝트입니다.

참가자는 단순한 기사 모음을 넘어 시간의 흐름과 주요 사건, 관점의 변화, 남은 질문을 하나의 긴 글로 완성합니다. 각자의 글은 초조한 전망대 공동 서적으로 발간합니다.

## 우리가 던지는 질문

- 한 주제를 4개월 동안 꾸준히 따라가면 처음의 생각은 어떻게 달라질까?
- 흩어져 보이던 사건을 시간순으로 놓으면 어떤 흐름과 전환점이 보일까?
- 뉴스 요약을 넘어 자신의 질문과 관점을 가진 글로 발전시키려면 무엇이 필요할까?
- 에이전트는 자료 수집과 정리를 어디까지 맡을 수 있고, 사람은 어떤 판단을 끝까지 책임져야 할까?

## 목표

### 1. 뉴스 여정을 책으로 발간하기

참가자마다 하나의 주제를 정해 4개월 동안 관련 뉴스를 추적합니다. 마지막에는 기록을 하나의 서사와 주장으로 재구성하고, 각자의 글을 묶어 공동 서적으로 발간합니다.

### 2. 관심사를 관점이 있는 글로 발전시키기

- 시작할 때 주제와 핵심 질문을 명확히 정합니다.
- 매주 핵심 뉴스를 읽고 선택 이유와 생각을 기록합니다.
- 사건 간 연결, 이해관계자, 반복되는 주장과 반론을 추적합니다.
- 중간 회고에서 처음의 가설과 관점이 어떻게 바뀌었는지 점검합니다.
- 4개월의 기록을 하나의 서사와 주장으로 완성합니다.

### 3. 리서치와 집필을 돕는 에이전트 만들기

OCI 환경에 공용 에이전트 시스템을 구성하고 실제 활동에 사용합니다. 에이전트는 사람을 대신해 결론을 쓰는 도구가 아니라, 놓치기 쉬운 자료를 찾고 기록을 구조화하며 반론과 빈틈을 보여주는 동료로 설계합니다.

## 주제 선정 기준

주제는 넓은 분야명보다 **4개월 동안 변화와 논쟁을 관찰할 수 있는 질문**의 형태로 정합니다.

| 넓은 주제 | 관찰 가능한 질문 |
| --- | --- |
| AI | 생성형 AI 도입이 주니어 개발자의 역할을 어떻게 바꾸는가? |
| 전기차 | 전기차 캐즘 논쟁 속에서 배터리 산업의 투자 방향은 어떻게 변하는가? |
| 지역 소멸 | 지역 소멸 대응 정책에서 청년 정착보다 관광이 앞서는 이유는 무엇인가? |

주제 선언문에는 다음 내용을 담습니다.

1. 4개월 동안 따라갈 주제
2. 지금 이 주제가 중요하다고 생각하는 이유
3. 출발점에서 가진 가설 또는 선입견
4. 계속 확인하고 싶은 핵심 질문 2~3개
5. 우선적으로 볼 매체·기관·전문가·당사자
6. 주제의 범위와 다루지 않을 범위

## 4개월 로드맵

| 단계 | 초점 | 주요 활동 | 산출물 |
| --- | --- | --- | --- |
| 준비 주간 | 질문과 범위 정하기 | 주제 선언, 키워드·출처·알림 조건 설정, 검증 원칙 공유 | 주제 선언문, 초기 가설, 출처 지도 |
| 1개월 차 | 넓게 읽고 지형 파악하기 | 핵심 뉴스 선정, 주요 행위자와 반복 쟁점 파악 | 뉴스 카드 4회, 주제 지도, 1차 월간 메모 |
| 2개월 차 | 연결하고 비교하기 | 타임라인 작성, 매체 프레임과 이해관계자 관점 비교 | 타임라인, 관점 비교표, 중간 발표, 2차 월간 메모 |
| 3개월 차 | 관점과 논지 세우기 | 전환점 선정, 잠정 주장과 목차 작성, 근거·반론 연결 | 장별 목차, 핵심 주장, 근거 목록, 원고 초안 |
| 4개월 차 | 쓰고 검증하고 엮기 | 초안 집필, 동료 피드백, 사실·인용·링크 검증 | 최종 원고, 참고문헌, 공동 서문·후기, 출판 원고 |

## 주간 기본 루틴

1. **에이전트 브리핑 확인** — 수집된 후보 뉴스와 변화를 살펴봅니다.
2. **핵심 뉴스 선택** — 반드시 읽을 기사 1~3건을 사람이 결정합니다.
3. **뉴스 카드 작성** — 사실, 맥락, 생각, 남은 질문을 기록합니다.
4. **짧은 공유** — 온라인에서 3~5분 동안 이번 주의 변화를 소개합니다.
5. **상호 질문** — 다른 참가자가 반론, 연결점 또는 추가 출처를 제안합니다.
6. **아카이빙** — 기사, 메모, 질문과 인용을 공용 저장소에 축적합니다.

### 뉴스 카드 템플릿

- 기사 제목 / 출처 / 날짜 / 링크
- 세 문장 사실 요약
- 이 뉴스가 내 주제에서 중요한 이유
- 이전 뉴스와 연결되는 지점
- 이해관계자별로 다르게 보이는 지점
- 내가 동의하지 않거나 의심하는 부분
- 다음 주에 확인할 질문
- 최종 원고에 사용할 가능성: 높음 / 보통 / 낮음

## 모임 구성

- **주간 비동기 기록:** 각자 뉴스 카드 작성
- **격주 온라인 모임:** 핵심 변화 공유와 질문 중심 토론
- **월말 리뷰:** 한 달의 흐름을 긴 메모로 정리
- **중간 합평:** 2개월 차에 주제·관점·논지 점검
- **오프라인 집필 워크숍:** 목차와 초안을 함께 다듬기
- **최종 합평:** 출판 전 사실 검증과 편집 방향 통일

발표를 길게 준비하기보다 사전에 기록한 뉴스 카드와 질문을 중심으로 대화합니다. 진행자는 내용을 평가하기보다 더 깊이 볼 질문과 서로 연결되는 지점을 찾습니다.

## 최종 결과물

공동 서적은 다음 흐름으로 구성합니다.

1. 왜 우리는 뉴스를 4개월 동안 따라갔는가
2. 읽고, 쓰고, 에이전틱하게 작업한 방식
3. 참가자별 장
4. 주제 간 연결 지도
5. 에이전트와 함께한 리서치의 가능성과 한계
6. 4개월 후에도 남은 질문

참가자별 원고는 **한국어 약 8,000~15,000자**를 기본 범위로 하며, 참가자 수와 출판 방식에 따라 조정합니다.

완성된 대표 원고는 선택적으로 오디오 에세이, 카드뉴스, 숏폼 비디오 등으로 확장합니다. 모든 파생 콘텐츠는 검증된 기준 원고와 출처 목록을 공유하며 사람이 최종 검수합니다.

## OCI 에이전트 MVP

하나의 메인 에이전트가 세션 목표를 해석하고 필요한 Skill과 Tool을 선택하는 구조로 시작합니다. Subagent는 병렬 조사나 독립 검증처럼 별도 컨텍스트가 실제로 필요할 때만 사용합니다.

### 초기 Skill

- **뉴스 리서치:** 후보 기사 수집과 큐레이션
- **분석·검증:** 타임라인, 반론, 누락 관점과 사실 확인
- **집필·편집:** 뉴스 카드, 목차와 원고 초안 지원
- **운영·아카이빙:** 승인된 기록 저장과 활동 관리

### 초기 Tool

- 키워드·RSS·지정 매체 기반 뉴스 후보 수집
- 기사 원문과 메타데이터 조회
- 중복 기사 후보 탐지
- 기사, 뉴스 카드, 인용과 질문 저장·조회
- 주제별 타임라인과 과거 기록 검색
- 숫자·날짜·인용·링크 검증 보조
- 주간 브리핑 데이터 조회와 일정 실행

MVP는 **메인 에이전트 + 뉴스 리서치 Skill + 검색·RSS 수집·저장 Tool + 주간 브리핑 스케줄러**부터 구현합니다.

## 사람과 에이전트의 역할

| 에이전트에게 맡기는 일 | 사람이 끝까지 맡는 일 |
| --- | --- |
| 넓게 찾고 반복 작업 줄이기 | 중요한 뉴스 선택하기 |
| 자료를 같은 형식으로 정리하기 | 출처의 신뢰성 판단하기 |
| 이전 기록과 연결 후보 찾기 | 사실과 해석 구분하기 |
| 빠진 관점과 확인 질문 제안하기 | 주장과 문체 결정하기 |
| 검증이 필요한 지점 표시하기 | 민감한 내용·저작권·최종 원고에 책임지기 |

> 에이전트가 만든 요약은 출처가 아닙니다. 모든 핵심 주장과 인용은 원문으로 돌아가 확인합니다.

## 참여 역할

기술 배경과 무관하게 참여할 수 있으며 역할은 순환합니다.

- **관찰자:** 새로운 사건과 자료 발견
- **질문자:** 당연하게 받아들인 전제에 질문
- **연결자:** 다른 주제·과거 사건·참가자 기록과 연결
- **팩트체커:** 숫자·날짜·인용을 원문과 대조
- **편집자:** 글의 흐름과 독자의 이해 점검
- **메이커:** OCI 에이전트와 자동화 기능 구현

모든 참가자가 개발할 필요는 없습니다. 좋은 출처, 분류 기준, 질문, 실패 사례와 편집 피드백도 에이전트 설계의 중요한 기여입니다.

## 로컬 개발

### 요구 사항

- Node.js 20 이상
- pnpm
- Supabase 프로젝트

### 실행

```bash
pnpm install
cp .env.local.example .env.local
pnpm dev
```

`.env.local`에 다음 값을 설정합니다.

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key-here
```

주요 명령어는 다음과 같습니다.

```bash
pnpm dev     # 개발 서버
pnpm lint    # 정적 검사
pnpm build   # 프로덕션 빌드
pnpm start   # 프로덕션 서버
```

## 우리가 남기려는 것

결과물은 책 한 권만이 아닙니다.

- 한 주제를 오래 관찰하는 습관
- 뉴스에서 사실과 해석을 구분하는 방법
- 흩어진 기록을 관점이 있는 글로 만드는 경험
- 에이전트를 맹신하지 않고 동료처럼 설계하고 검증하는 기준
- 다음 시즌에도 재사용할 수 있는 리서치와 집필 인프라

**초조함은 뉴스를 더 많이 보는 것으로 사라지지 않습니다. 한 걸음 물러나 오래 바라보고, 기록하고, 연결하고, 자기 언어로 써볼 때 전망이 생깁니다.**
