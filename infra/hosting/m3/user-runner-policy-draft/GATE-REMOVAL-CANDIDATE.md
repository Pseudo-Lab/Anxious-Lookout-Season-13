# Issue10 gate-removal candidate — source review only

This proposal replaces the incomplete hand-written main validations with checks
generated by `backend/ops/runner_policy.py`. It does **not** change the existing
`admission.json.in` literal false gate, a live policy, quota or cluster. Review
this implementation, the exact PM-input render, and a bounded server-default
observation plan before PM removes any gate. The main policy denies every UPDATE;
scheduler binding and pods/status are separate resources and are not matched.
The subresource policy remains unconditional false for ephemeralcontainers UPDATE
and exec/attach/portforward CONNECT. No wildcard selector or exception is added.

## Disposition method

The fixed upstream schema inventory is hash-checked before generation. Every
PodSpec/ObjectMeta member receives one of these dispositions in `dispositions.json`:

- `exact`: every emitted Plan scalar, map and ordered list is compared. The
  generated predicates enumerate schema object properties; they never enumerate
  typed objects as maps. All unselected properties at each accepted object are
  explicitly absent. Lists have exact length and element contents; maps have
  exact equality. Env duplicates, foreign valueFrom, duplicate volume sources,
  extra mounts, list duplicates and privilege overrides cannot hide behind exists.
- `absent`: an unselected field is absent, and its **entire schema subtree** is
  forbidden. The row names the reference/type. There is no need to admit or
  independently traverse the children of an absent parent. This includes unused
  volume sources, probes, resource overrides, scheduling/runtime knobs, annotations,
  finalizers, ownerReferences, nodeName, hostUsers and all newly inventoried fields.
- `server-default-whitelist`: defaults are a deliberately narrow **candidate**:
  serviceAccount alias, default-scheduler, priority0, PreemptLowerPriority, the
  ordered unique not-ready/unreachable NoExecute Exists300 pair, container empty
  resources, terminationMessagePath=/dev/termination-log and policy=File. Missing
  candidate defaults fail rather than silently enlarging the allowed set. Verify
  actual server output before persisted create. If plugins produce another order
  or omit a field, stop and review the difference; do not auto-normalize it.

The three nonpointer host namespace booleans are an explicit serialization case:
false or omitted is allowed, true is denied. The official v0.36.4 native Pod JSON
roundtrip is tested. Pointer security booleans are not made optional. KubePods
lookup normalizes only those three missing booleans to false, retaining full spec
comparison and foreign-reference rejection.

Metadata uid/resourceVersion/creationTimestamp/managedFields/generation are typed
server evidence, not execution grants. Their values are not trusted as caller
identity or object references. This policy does not distinguish server-populated
metadata from caller-supplied evidence fields; the future one-shot wrapper must
submit the exact Plan metadata (name/namespace/labels only), and validate returned
UID separately. No foreign metadata-based exemption is introduced. Other metadata
is absent. Pod root apiVersion/kind are exact; status is not part of the execution
spec and the policy never matches pods/status. The core API remains responsible
for schema validation/unknown field handling; CEL is not a substitute for that.

## Typed evidence

Run `bash infra/hosting/m3/user-runner-policy-draft/validate-candidate.sh` from the
repo. All generation/tests/Go builds run in Docker. Go dependencies are pinned in
celcheck/go.mod/go.sum; only the dependency preparation container uses network.
The generator, pytest and CEL evaluation containers use network none, read-only
root and dropped capabilities. Evidence is left in a fresh /tmp directory.

The Go harness uses Kubernetes apiserver v0.36.4 SchemaDeclType, its v1.36 base
CEL environment, and OpenAPI UnstructuredToVal. The root Pod schema adds the
explicit apiVersion/kind and the full pinned spec/metadata. Only request fields
used here (operation, userInfo.username) are declared, with string types; they are
not dyn maps. Unknown spec field compilation must fail. Every expression must
compile to bool, evaluate true on the synthetic defaulted Pod and native Pod JSON
roundtrip, and false on its independent mutations without an evaluation error.
Nested leaf and absent-member mutations supplement per-expression negatives.
The literal false gate is excluded from all those results; it cannot mask tests.
Literal quote/backslash/control-character encoding is evaluated by CEL itself.

These tests do not run an API server, admission plugin chain, Cilium schema or
network datapath. They do not claim PSA/RBAC/quota failures as CEL evidence, or
that source defaults equal this k3s cluster's defaults. Compile/type-check and
synthetic evaluation are necessary inputs to the two-stage PM observation review.

## Separate policy renderer and exact artifacts

`python -m ops.runner_policy` runs in an exact reviewed runtime Docker image with
`--values`, `--inventory`, `--network-template` and `--output`. The validation
script demonstrates invocation using mounted working source. Inputs are public
image digest, HTTPS callback and namespace/SA/port, plus observed quota
resourceVersion. See schema/synthetic-values.json for the **test-only** shape;
its image, callback and quota version are not deployable PM values. No tokens or
DB DSNs are accepted. Namespace/owner/state/references are fixed to Issue10.
Image and callback must be reviewed against the actual runner image and callback
endpoint; the renderer's syntax validation is not an operator attestation.

The reviewed network template and schema are separately hash pinned. Network
substitution is JSON-value aware. CEL is generated using double-quoted encoded
literals; no value is substituted into a quoted CEL template. Unknown/missing
input keys, invalid image/URL/ports and unresolved placeholders fail closed.
Outputs are a new private directory, exclusive-create files and a SHA256 index.
No apply command or kube credentials exist in the renderer. A partial I/O failure
preserves evidence; do not auto-retry into the same output path.

Artifacts are deliberately separate, not a multi-document apply bundle:

- network-00/01/02.json: existing exact CNP drafts with selected A host ingress;
  retained controller SA egress does not restrict the diagnostic host process.
- gate-retained-00..03.json: generated VAP/bindings, main gate still false.
- gate-removal-candidate-00..03.json: the same objects without only the main gate;
  subresource false remains. These are **review candidates**, not apply approval.
- quota-1.json and quota-0.json: named rehearsal quota with input resourceVersion.
  PM must use reviewed conditional replacement semantics, not apply that discards
  the version precondition. Both files represent the same observed snapshot:
  after changing quota, the restore file is stale. Re-read the current version,
  re-render and review the exact restore artifact; never strip resourceVersion.
- plan.json, synthetic-defaulted.json, dispositions.json and suite.json: evidence,
  **not apply inputs**. The synthetic-defaulted object must never be created.

## Proposed bounded observation order

1. Review these sources/test evidence and exact public PM values/image provenance.
   Render and review digest/index, CNP schema and effective inherited policy union.
2. PM records existing policies/bindings and quota resourceVersion, namespace and
   storage/Secret UIDs, no existing Pod, and reviewed caller RBAC. Do not leave
   an older unconditional false policy matching alongside the new candidate and
   then misreport its rejection as an individual CEL result. Any old-policy
   replacement/removal needs an explicit rendered transition plan.
3. Under separately approved observation procedure, PM installs only the reviewed
   candidate and temporarily quota1 with version precondition. Server dry-run of
   exact Plan/caller must succeed without warnings; compare returned defaults to
   candidate and adapter. Unexpected output stops before persisted creation.
4. Persisted create still waits for the initializer/image checks, durable one-shot
   wrapper and probe package review. This source proposal does not authorize a
   manual kubectl create. Restore quota0 with a fresh versioned artifact, retaining
   all evidence/one-shot permit; quota0 does not prove drain or delete the Pod.
