## Refresh ownership: native vs the original host

Managed Codex0.160.1 performs actual refresh in the **private runner's CODEX_HOME/auth.json**. The adapter never implements external-token refresh and never refreshes the original host file. After a clean quiescent native exit it transfers the updated private cache back to the approved control directory and removes the local runtime cache. That directory is the private trial's authoritative credential/ledger store, separate from native-home backups.

An existing host CLI/IDE/other process using the **same renewable session** may independently refresh or logout, even if source files are read-only. The runner's file/volume locks only coordinate this implementation. They cannot compel an unrelated host process to participate. Current implementation has **not** established absence of such processes or a safe handoff for the user's existing session.

Before any cache supply, PM must independently establish one refresh owner for that renewable session without an unauthorized original logout/cache rewrite/development-session interruption. The grant's hostGrantQuiescent/procedureReviewed fields only record the operator decision; they do not discover or prove host state. If unchanged active host sessions cannot cooperate, **do not copy or activate this candidate**. Report that safe simultaneous reuse is unproven and seek a supported, explicitly authorized private-session arrangement. This code does not silently create a new login, stop existing agents, return rotated tokens to the host or substitute API billing/SIWC UI. The [official accounts/session guidance](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) also requires latest rotating token storage and same-session refresh serialization; it does not promise unchanged-host coexistence for copied caches.

## Maximum3 explicit dispatches and observations

The control ledger charges before native reservation/model work. Failed thread/resume/model attempts, ambiguous reservation failure and turns after process restart all consume the same3-slot budget. Exact native retries with a durable matching reservation are no-ops. If a control request exists but the native reservation was rolled back/lost/restored, dispatch is refused as ambiguous. Restoring an old native home cannot roll back the external ledger. An unclean native process exit leaves nativeActive=true and prevents automatic reactivation of old credentials; PM reconciliation is required. The cap is on explicit native dispatches, not a claimed count of opaque provider-internal HTTP retries or dynamic calls within one turn. New platform turns are never auto-replayed.

The pin exposes requested model in thread/start/resume responses and model/rerouted events. ## Stop, cleanup, backup and failure

Stop admission and quiesce active work before stopping the native process. A bounded callback shutdown that remains ambiguous leaves the control tombstone active; no clean-resume claim. Clean exit syncs only this trial's private updated cache and deletes the runtime auth.json. It never logs out/rewrites the original host or invokes provider revocation.

Then use the reviewed container CLI:

```sh
python -m runner.auth --control /run/personal-control --cleanup --native-root /state
```

It marks the private grant revoked before cleanup, obtains the private lease, deletes control/runtime auth.json for the bound owner, and retains the grant/dispatch ledger tombstones and native conversations. If another process still holds the lease, cleanup fails after revoking admission; stop/reconcile that owned process and retry cleanup. This is **local** revocation; it does not revoke the provider renewable session or prove host non-interference. Shared-session provider logout/revocation remains a separately approved operator action.

Back up only after a clean quiescence/cleanup, preserving private DB/native content and exact image/pin metadata. Exclude credential files/temp authentication artifacts, keep control/ledger tombstones separate and retain encrypted private originals, which may contain provider diagnostic data. Restore source data to a new account-bound private candidate without auth caches; never restore an old control snapshot or clear nativeActive/dispatch counters to resume. A fresh authoritative, approved credential source/ownership decision is necessary for any later trial. If authentication interrupted refresh or state was ambiguous, preserve metadata privately and do not resurrect the source through a backup. Docker fixtures prove these software gates, not real-host/session/provider recovery.
